# 銀行管理系統 - 系統操作與編譯指南

本文件說明如何建立執行環境、編譯 COBOL 程式碼以及操作銀行管理系統的各項選單功能，並深入剖析系統內部的核心算法與技術設計。

> [!WARNING]
> 本專案僅作為程式碼寫法範例展示，並未實作任何資料加密或安全防護機制（如身分證字號、電話、餘額與交易明細等敏感資訊均為明文儲存）。請勿直接將本專案套用於實際的生產系統或商業環境中。

---

## 1. 環境建置與安裝 (WSL Debian/Ubuntu)

如果您使用的是 Windows 系統，建議透過 **Windows Subsystem for Linux (WSL)** 搭配 Debian 或 Ubuntu 發行版來運行 GnuCOBOL 編譯器。

### 步驟 1: 啟用 Windows 的 WSL 功能
1. 以系統管理員身分開啟 PowerShell。
2. 執行以下指令啟用 Windows 子系統功能：
   ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
   ```
3. 依系統提示重新啟動電腦。

### 步驟 2: 安裝與啟動 Linux 發行版
1. 開啟 PowerShell，輸入以下指令安裝 Debian 發行版：
   ```powershell
   wsl --install -d Debian
   ```
2. 安裝完成後會自動開啟 Linux 終端機，依提示設定您的使用者名稱與密碼。

### 步驟 3: 安裝 GnuCOBOL 編譯器
1. 在 Linux 終端機中，執行套件更新指令：
   ```bash
   sudo apt-get update
   sudo apt-get upgrade
   ```
2. 安裝 GnuCOBOL 編譯器：
   ```bash
   sudo apt-get -y install gnucobol
   ```
3. 確認編譯器安裝成功與版本：
   ```bash
   cobc --version
   ```

## 2. 程式編譯與執行

本專案的 COBOL 原始碼位於 [BANK.cbl](../BANK.cbl)。請遵循以下步驟進行編譯與執行：

### 步驟 1: 編譯 COBOL 程式
在 Linux 終端機進入專案目錄，執行以下編譯指令：
```bash
cobc -x -free BANK.cbl -o BANK
```
* `-x`：產出獨立可執行的二進位檔 `BANK`。
* `-free`：指示編譯器使用自由格式（Free Format）撰寫的代碼，不受傳統 COBOL 第 1-6 欄與 72-80 欄之格式限制，以便在現代編輯器中閱讀與修改。
* `-o BANK`：指定輸出檔名為 `BANK`。

### 步驟 2: 執行程式
在終端機中輸入以下指令啟動系統：
```bash
./BANK
```

## 3. 系統選單操作說明

執行程式後，系統會顯示如下主選單介面：

```text
===============================
      銀行管理系統選單         
===============================
1. 新增客戶資料
2. 開立新帳戶
3. 存款
4. 提款
5. 轉帳
6. 查詢餘額
9. 離開系統
===============================
請輸入您的選擇 (1-9): 
```

### 功能 1：新增客戶資料
* **說明**：建立新客戶的個人基本資訊。
* **流程**：
  1. 輸入 `1` 並按下 Enter。
  2. 系統會自動計算並顯示即將生成的客戶 ID（如 `新客戶ID: 000005`）。
  3. 依序輸入以下欄位：
     * **身份證字號**：必須符合格式（英文字母開頭加上 9 位數字，如 `A123456789`）。系統會自動執行台灣身分證字號加權驗證。若格式不符，會要求重新輸入。
     * **客戶姓名**：輸入客戶的姓名，不得為空。
     * **客戶地址**：輸入客戶的聯絡地址。
     * **聯絡電話**：輸入電話號碼。
  4. 確認資料無誤後，輸入 `Y` 存檔。系統會將資料寫入 [CUSTOMER.SAM](../CUSTOMER.SAM)。

### 功能 2：開立新帳戶
* **說明**：為已建立的客戶開立新的儲蓄或支票帳戶。
* **流程**：
  1. 輸入 `2` 並按下 Enter。
  2. 輸入要綁定的 **客戶 ID**。
  3. 系統驗證客戶 ID 是否存在於 [CUSTOMER.SAM](../CUSTOMER.SAM)：
     * 若不存在，顯示錯誤訊息並返回主選單。
     * 若存在，生成唯一帳號，並提示選擇帳戶類型：
       * 輸入 `S`：開立儲蓄帳戶 (Savings)
       * 輸入 `C`：開立支票帳戶 (Checking)
  4. 輸入 **初始存款金額**。
  5. 系統會自動取得當前系統日期作為開戶日期，並將帳戶狀態設為啟用（Active），寫入 [ACCOUNT.SAM](../ACCOUNT.SAM)，同時在交易歷史檔 [TRANS.SAM](../TRANS.SAM) 中寫入一筆「初始存款」紀錄。

### 功能 3：存款作業
* **說明**：將資金存入指定的帳戶中。
* **流程**：
  1. 輸入 `3` 並按下 Enter。
  2. 輸入要存入的 **帳號**。
  3. 系統會驗證帳號是否存在、是否已關閉（Closed）或凍結（Suspended）。
  4. 輸入 **存款金額**（必須大於零）。
  5. 系統透過安全暫存機制更新該帳戶的餘額，並在 [TRANS.SAM](../TRANS.SAM) 記錄一筆型態為 `D`（Deposit）、描述為「櫃台存款」的交易明細。

### 功能 4：提款作業
* **說明**：從指定帳戶中提取資金。
* **流程**：
  1. 輸入 `4` 並按下 Enter。
  2. 輸入 **帳號**。
  3. 系統驗證帳號狀態，並提示輸入 **提款金額**。
  4. 系統檢查帳戶餘額是否足夠：
     * 若餘額不足，顯示錯誤訊息並中止提款。
     * 若餘額充足，更新餘額，並在 [TRANS.SAM](../TRANS.SAM) 記錄一筆型態為 `W`（Withdrawal）、描述為「櫃台提款」的交易明細。

### 功能 5：轉帳作業
* **說明**：將資金從來源帳戶轉移至目標帳戶。
* **流程**：
  1. 輸入 `5` 並按下 Enter。
  2. 輸入 **來源帳號** 與 **目標帳號**（兩者不能相同，且帳戶狀態必須為啟用）。
  3. 輸入 **轉帳金額**。
  4. 系統檢查來源帳戶餘額是否足夠：
     * 若不足，顯示錯誤並退出轉帳。
     * 若充足，分別扣除來源帳戶餘額、增加目標帳戶餘額。
  5. 系統會在 [TRANS.SAM](../TRANS.SAM) 寫入兩筆交易紀錄：
     * 來源帳戶寫入一筆型態為 `T`（Transfer）、描述為「轉出至帳號: [目標帳號]」的交易。
     * 目標帳戶寫入一筆型態為 `T`（Transfer）、描述為「轉入自帳號: [來源帳號]」的交易。

### 功能 6：查詢餘額
* **說明**：顯示帳戶當前狀態、關聯客戶資訊以及最近 5 筆交易明細。
* **流程**：
  1. 輸入 `6` 並按下 Enter。
  2. 輸入 **帳號**。
  3. 系統顯示該帳戶的：
     * **帳戶資訊**：帳號、客戶 ID、類型、餘額、開戶日期、狀態。
     * **客戶資訊**：姓名、身分證字號、地址、電話。
     * **最近5筆交易記錄**：包含日期、時間、類型（存款/提款/轉帳）、金額、交易前後餘額與描述。

### 功能 9：離開系統
* **說明**：結束程式執行。
* **流程**：
  1. 輸入 `9` 並按下 Enter。
  2. 系統安全關閉所有開啟的資料檔案，顯示 `謝謝使用本系統，再見！` 並退出。

## 4. 系統設計與技術實作細節

### 台灣身分證字號驗證演算法

系統在新增客戶時，會自動針對身份證字號欄位（1 位大寫英文字母 + 9 位數字）進行合法性校驗。演算法實作於 `950-VALIDATE-ID` 段落中：

1. **英文字母對應數值**：
   將第一個字母轉換為二位數字，十位數存於 `WS-ID-N1`，個位數存於 `WS-ID-N2`。對應表如下：
   * `A` -> 10, `B` -> 11, ..., `I` -> 34, `O` -> 35, `W` -> 32, `Z` -> 33 （部分字母有特別對應，如 I, O, W, Z）。

2. **加權相乘公式**：
   其餘第 2 至第 10 碼（`N3` 到 `N10`，其中 `N10` 是身分證最後一碼）分別乘上固定權重，並與字母轉換值累加求和：
   $$\text{Sum} = (N1 \times 1) + (N2 \times 9) + (N3 \times 8) + (N4 \times 7) + (N5 \times 6) + (N6 \times 5) + (N7 \times 4) + (N8 \times 3) + (N9 \times 2) + (N10 \times 1)$$

3. **求餘數與比對**：
   * 計算餘數：$\text{Remainder} = \text{Sum} \bmod 10$。
   * 計算校驗碼：若 $\text{Remainder} = 0$，校驗碼為 $0$；否則校驗碼為 $10 - \text{Remainder}$。
   * 系統將此校驗碼與身分證第 10 碼（最後一位數字）進行比對，完全吻合才算驗證通過。

### 安全檔案更新機制

為避免檔案寫入時程式異常中斷導致原始帳戶資料檔案損毀，系統實作了暫存安全更新機制：

1. **暫存檔寫入**：進行任何交易時，程式會開啟 [ACCOUNT.SAM](../ACCOUNT.SAM) 進行唯讀讀取，同時開立一個暫存檔 [TEMP-ACCOUNT.SAM](../TEMP-ACCOUNT.SAM) 進行寫入。
2. **資料移轉與更新**：程式將不需要更新的帳戶資料原封不動寫入暫存檔，當讀取到當前交易的帳戶時，將更新後的餘額與欄位寫入暫存檔中。
3. **重新命名覆蓋**：所有寫入確認完成後，程式關閉這兩個檔案，並呼叫 COBOL 系統函數：
   ```cobol
   CALL "CBL_RENAME_FILE" USING "TEMP-ACCOUNT.SAM" "ACCOUNT.SAM"
   ```
   以暫存檔案安全地覆蓋舊資料，確保檔案讀寫的一致性。

### 最近交易記錄環形緩衝區 (Ring Buffer)

在記憶體受限的環境下，為了能以最有效率的方式提取並顯示某個帳戶最新的 5 筆交易，系統採用了 Ring Buffer 設計：

1. **宣告靜態陣列**：在 `Working-Storage Section` 中宣告一個包含 5 個元素的表格結構：
   ```cobol
   05  WS-RING-ENTRY  OCCURS 5 TIMES.
       10  WR-ID      PIC X(12).
       ...
   ```
2. **循序讀取與循環覆寫**：
   系統遍歷讀取完整的交易檔案 [TRANS.SAM](../TRANS.SAM)。每當讀到一筆與查詢帳號相吻合的交易時，系統會累加符合條件的交易計數器 `WS-TRANS-TOTAL`，並利用以下公式計算在陣列中的寫入位置：
   $$\text{Write-Index} = (\text{WS-TRANS-TOTAL} - 1 \bmod 5) + 1$$
   隨後將該筆紀錄覆寫至 `WS-RING-ENTRY(Write-Index)` 中。
3. **依序輸出**：
   當檔案讀取完畢後，如果總交易筆數少於 5 筆，系統將從第 1 格依序輸出至第 `WS-TRANS-TOTAL` 格；如果大於等於 5 筆，系統會計算出最舊的交易在環形緩衝區中的起始索引，並連續輸出 5 筆紀錄，以此完成由舊到新且記憶體佔用極低的分頁顯示。
